# 刺杀、任务人数与连续否决 UI 收尾

本次仅小程序前端 UI / presentation 修改，无需重新部署后端。
未修改数据库、SQL、API、游戏角色或连续五次否决规则。

## 显示语义

- ASSASSINATION 的不可选择与变暗分离：公开邪恶使用 `unselectable`，不使用 `disabled`。
  Lady 等原有禁用场景继续使用 `disabled`，维持 0.4 透明度。
- 公开邪恶固定红环 `#C85C68`，保留娜 / 刺 / 爪 / 莫 / 奥具体角色徽记。
  刺客选中的好人使用 `selected-assassination` 与 `#FFD166` 琥珀黄环。
  公开邪恶即使有旧选择草稿，也不会获得黄环。公开数据来源及隐私边界不变。
- 提前 / 正常刺杀统一顶部卡片“最终刺杀”，副文案
  “刺中梅林，邪恶获胜；刺错则正义获胜”。刺客中心“请选择刺杀梅林”，
  选择后补“已选择：N号 玩家名”；其他玩家只有“等待刺客选择梅林”。
  发动提前刺杀与最终刺杀的危险操作确认弹框不变。
- 未完成任务圆点读取 `rules(n).teamSizes`（现有 TEAMS 的副本），展示任务人数，
  当前轮金底、未来轮暗底；已完成仍为 ✓ / ×，原有完成任务详情点击保持不变。
  圆点 48rpx，人数 24rpx，✓ / × 保持原有继承字号。
  5 人 `[2,3,2,3,3]`，6 人 `[2,3,4,3,4]`，7 人 `[2,3,3,4,4]`，
  8 / 9 / 10 人 `[3,4,4,5,5]`，组件内不复制规则表。
- 只有 TEAM_BUILDING / TEAM_VOTING 的圆桌中央显示否决圆点。
  `rejectionState(game)` 根据服务端 `consecutiveRejections` / `maxRejections`
  返回布尔数组；圆点 20rpx、间隔 9rpx、行高至少 32rpx，已否决红色、未使用暗底边框。
  `consecutiveRejections === maxRejections - 1` 时提示“⚠ 强制轮”及
  “本轮若再次否决，邪恶阵营直接获胜”。不是根据 proposalNo 判断。
- 强制轮不改变业务流程：选队后仍进入 TEAM_VOTING，仍可投同意 / 反对，
  第五次连续否决依旧由后端 FIVE_REJECTED_TEAMS 判胜。删除底部否决计数及当前队长文案。
- 皇冠普通 42×42rpx、字 26rpx、top -16rpx；9 / 10 人 compact
  36×36rpx、字 23rpx。身份徽记继续 38 / 34rpx，✓ 继续 30rpx，我的徽记不变。
  圆桌高度不增长，中央提示按内容居中；强制轮稍上移避免撞到底部头像。
