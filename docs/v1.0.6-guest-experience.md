# V1.0.6 游客体验版本

登录页保留圆形 A 标识、阿瓦隆标题、宣传语与微信授权按钮，新增 2×2 的游戏规则、角色介绍、人数配置和体验玩法入口。四个页面可直接访问，也可返回登录页。授权函数、用户协议和隐私政策文案没有改动。

## 玩法与边界

- 规则和配置读取现有 presentation 配置；自动测试核对 Java GameRuleConfig 的任务人数和失败阈值。
- 八种角色复用 cards.js 的现有公开 HTTPS 图片地址。新增资源仅为五个小尺寸 SVG，不重复打包卡牌。
- 体验房间固定一名体验玩家、四名机器人。可逐个添加或补满；每局使用 Fisher–Yates 洗牌，随机首任队长。
- 本地引擎校验确认身份、组队、全员表决、秘密任务、连续否决、胜负及刺杀。机器人参考现有 Java 的简单概率策略：70% 赞成，邪恶 70% 出失败，选队包含自己；刺客从公开合法目标中随机选择。
- 策略只接收当前行动者的身份视野及公开信息。其他角色和未公开任务牌留在引擎闭包内，页面只获取游客的投影视图。任务记录只展示匿名牌数。
- 任务结算沿用现有动画；确认前暂停机器人，确认后继续。阶段、状态版本和页面生命周期共同阻止重复操作及旧回调。
- 支持结束本局、提前刺杀、重新随机开局、退出确认。退出销毁引擎，隐藏页面暂停定时器，返回页面继续；不读写正式对局或战绩存储。
- 体验引擎不调用微信登录、用户资料接口、正式房间接口、JWT 或 WebSocket。无需后端部署、数据库迁移；没有上传小程序或提交审核。

## 验证

- `npm --prefix miniprogram test`：682 项通过（包括 200 局种子随机完整对战）。
- `npm --prefix miniprogram run check`：JavaScript 语法检查通过。
- 微信开发者工具 iPhone 12/13 mini（375×812）：109 项检查通过。实际点开四个入口，查看角色卡、切换人数、完整走到任务结算与胜负，验证再来一局和退出。调用监测中 login、getUserProfile、request、connectSocket 均为零。
- Chrome 对导出的实际登录页 DOM 和 WXSS 检查 320×480、320×568、375×667、375×812、390×844、430×932：检查卡片排列、一致尺寸、按钮间距、水平溢出和短屏滚动。
- 放大角色卡额外验证卡牌位于微信胶囊下方。
- 没有连接物理 iPhone；以上为模拟器和浏览器检查。卡牌图片依赖现有公开静态资源网络访问，游戏状态计算在本地完成。
