# 等待大厅与身份揭晓页面适配

本次只修改小程序前端。Java、数据库、登录、角色权限、实时选人接口与 WebSocket 协议均未修改。

## 布局与状态

- 等待大厅去掉房间信息卡片，使用上下两条细分隔线；房间号独占一行；房主的下一行等宽显示「＋机器人 / 复制 / 退出 / 关闭」，普通成员显示前三项且机器人始终禁用。接口与确认流程沿用原方法。
- 底部操作区与中间滚动区分离。普通成员始终只有邀请按钮；房主双按钮按未满/已满切换为 65:35 / 35:65。满员、非 WAITING 或 busy 时邀请按钮禁用且移除 `open-type=share`。开始按钮仍检查服务端 `room.canStart`、busy、人数和房主展示条件；新增 botAdding 互斥锁，只阻止并发操作，不让邀请按钮变色或让开始按钮显示加载。
- 大厅与身份揭晓页面使用限定视口的 Flex 容器，导航及大厅底部不参与滚动；只有中间 scroll-view 的内容超出时才有滚动范围。禁用该滚动区回弹，关闭 room 原生下拉刷新；原有 WebSocket 重连及五秒刷新保持不变。
- 大厅圆桌不再使用 flex:1、按人数 min-height 或依赖容器高度的百分比纵坐标。`lobbyGeometry` 以统一 rpx 基准同时计算横纵半径和自然高度：5/6 人半径 216rpx，7/8 人 260rpx，9/10 人 280rpx；按实际头像中心对齐圆心。8/10 人局略扩大左右侧相邻座位的角度间隔，仍沿同一圆周顺序排列，为昵称和房主标签留空间。`lobbySeats` 的响应式选项只在大厅启用，默认调用和正式对局位置计算不变；头像、昵称和房主标识组件不变。
- 身份卡牌仍为原来的 400×715rpx，发牌、翻牌、洗牌逻辑没有变化。715rpx 的桌面预留对应实际大卡牌高度，并非强行缩小卡牌；多条私人视野使内容超高时仍可查看确认按钮及人数提示。

## 添加机器人请求

原先通用 run() 设置 busy，底部按钮也绑定 busy，因而每次添加都会禁用邀请、显示开局加载。现在独立维护 botAdding：只在机器人按钮显示 loading；通用操作、开局、退出和关闭仍与其互斥。开局前重新检查服务端 canStart、房主、人数和阶段。添加前等待已有刷新并复查权限、人数；添加成功后等待旧 GET 结束再刷新，避免轮询/推送共用旧响应。房间切换或退出后不应用旧请求结果，失败后解除锁供重试。

最后一名机器人入座时，底部按满员规则正常交换宽度、颜色。若 WebSocket 的满员状态先于添加请求结束到达，开始按钮保持准备好的绿色但原生 disabled 仍锁定，直到请求结束；不会出现绿色→灰色→绿色或额外加载动画。自动化复现中由添加机器人引起的底部闪动已消除。

这些检查不等同于物理 iPhone/Android 真机、iOS 原生回弹或真实多人联网验收。未部署后端，未上传体验版或微信审核版本。
