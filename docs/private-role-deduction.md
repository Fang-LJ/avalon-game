# 私人身份推测

本功能仅修改小程序。本轮 backend、SQL、数据库、API、WebSocket 协议和生产配置均未修改；不需后端重新部署。

## 使用与边界

在 TEAM_BUILDING、TEAM_VOTING、MISSION_EXECUTING、LADY_OF_LAKE 长按其他玩家头像，打开居中 Modal。
标题只有「标注身份」，不显示玩家信息、阵营分组标题、当前判断、关闭或清除按钮。
动态候选统一两列：正义及蓝方使用 #78B7FF，邪恶及红方使用 #E88A94；选中态增强同色边框和背景。
宽度 84%（上限 640rpx）、圆角 30rpx、内边距 32rpx，高度随选项变化；无 scroll-view，极小窗口仅在超过 82vh 时允许溢出滚动。
再次点击已选项取消，点击其他项直接替换，成功后关闭；派西配对取消仍同时清除两人。
点击遮罩关闭但不修改笔记，面板 catchtap 防止误关。底部仅「再次点击已选身份即可取消标注」。
自己及系统已知具体身份的邪恶同伴不可标记；候选为空不显示空弹层。长按不主动调用任何震动 API。
单击仍用于选任务成员、Lady 对象、刺杀目标。组件吞掉同一次长按结束后的 tap，新的 touchstart 重置抑制状态，
不会因计时器到期误触，也不会吞掉下一次独立快点。

个人判断复用头像右下唯一 knowledge-icon，圆标主体只显示梅/派/忠/娜/刺/爪/莫/奥/蓝/红，
完全复用系统 role-mark 的尺寸、22rpx 字号、900 字重、实线边框及角色 tone。
额外问号由组件独立渲染在右上角：right -7rpx、top -8rpx，16rpx/900，暖金色，无独立背景或边框。
系统确定身份不带问号，派西未判断时仍是原紫色 candidate-mark。
清除推测后恢复原有月牙/候选问号或无标记，不残留外置问号。
不新增第二个身份徽记，不覆盖皇冠、完成标记、我、任务选中边框。

## 候选与数量

`presentation.roleConfig()` 为本地公开角色组成；Node 测试逐一与未修改的 GameRuleConfig 5～10 人配置比对。
`role-guesses.js` 是纯函数层，不导入请求、服务或 socket。

- 候选 = 本局公开组成 ∩ 系统私有知识允许的角色 ∩ 剩余名额。
- 剩余 = 总角色数 − 自己确定身份 − 其他确定身份 − 其他人的个人推测。
  编辑目标自身旧推测暂不扣减；忠臣按配置保留多个名额，不把所有角色当成唯一。
- 梅林：月牙只能推测本局存在的邪恶身份，但排除莫德雷德；非月牙可推测正义角色及本局存在的莫德雷德。
  自己的梅林名额已扣除，不泄露月牙玩家真实角色。
- 派西维尔：两个系统候选只允许 MERLIN/MORGANA。指定一人立即以一次本地写入设置另一人为互补身份；
  交换时同步交换，清除任意一个同时清除两人。其他玩家始终不能选这两个保留名额。
  不完整的系统候选响应暂停推测，不推断具体身份。
- 普通邪恶：系统确定的非奥伯伦同伴锁定并扣除名额；没有系统视野的玩家仍可推测剩余正义或奥伯伦。
  7 人刺客选择某人为奥伯伦后其他人不再出现奥伯伦；编辑该人仍可保留，清除后名额恢复。
- 奥伯伦：不假设其他邪恶的身份。自己的奥伯伦名额自然用完，其他候选根据公开组成计算。
- `guessCandidates()` 的具体角色与名额算法不变，`markCandidates()` 只在现有结果外扩展低精度笔记。
  `possibleAlignmentsForTarget()` 从系统允许角色、本局配置、当前身份及目标视野判断可能阵营，不读取具体标记或库存。
  普通邪恶未知目标按系统视野规则排除所有非奥伯伦邪恶身份，不能因为本局有莫德雷德就推导出未知邪恶同伴。
  `sideCandidates()` 将可能阵营映射为 GOOD_SIDE（蓝方）/EVIL_SIDE（红方），但梅林月牙和派西系统 pair 不提供任何 SIDE。
  梅林无月牙：5～8 人仅蓝方、9/10 人红蓝方；普通邪恶未知目标：5/6/8/9 人仅蓝方、7/10 人红蓝方。
  忠臣和奥伯伦未知目标提供红蓝方；派西非 pair 按系统排除梅林/莫甘娜后的角色判断阵营。
- 红蓝方没有人数或阵营名额限制，多个玩家均可怀疑为同一方；不会占用、增加或减少任何具体角色名额。
  清洗具体标记继续使用原库存规则，红蓝标记仅通过 `sideCandidates()` 校验；具体角色库存耗尽也不隐藏、不清除合法 SIDE。
  只有系统知识使某 SIDE 不再合法时才清除，例如目标变成确定同伴或梅林月牙；自己、移除玩家、非法 key 和派西 pair 同样拒绝。
- 蓝方圆标使用独立 blue tone（深蓝底 #213f63、蓝边 #4B86C6、文字 #78B7FF），红方复用原 evil tone；
  仍然都是 GUESS，沿用相同圆标尺寸与外置小问号，不新增 system knowledgeType。

## 本地隐私与生命周期

仅使用 `AVALON_ROLE_GUESSES_V1:{gameId}:{myPlayerId}`，myPlayerId 是 gamePlayerId，不是 userId。
值为 `{guesses: {"gamePlayerId": "ROLE_CODE"}}`，ROLE_CODE 也允许 GOOD_SIDE/EVIL_SIDE；旧 V1 具体判断保持兼容。
不持久化昵称、公开 DTO 或其他玩家的私有信息。
读取时清理不存在玩家、非法角色、自身、系统确定身份、容量超限及不完整派西配对。

推测只合并到当前设备的 displayPlayers；不写回 room.players、GameState、timeline、replay、JWT 或请求。
选择、交换、清除均不调用网络。原有公共状态 GET/刷新仍正常进行，不携带推测。
普通阶段 WebSocket 刷新保留本地判断；返回同一对局读取存储。更换 gameId/gamePlayerId 或重开等待大厅不继承旧判断。
离开页面关闭弹层，保留当前正常阶段笔记；弹层事件带作用域 nonce，过期点击不会应用到新目标/新对局。

收到 ASSASSINATION/FINISHED 的 GameState 立即删除当前存储和内存、关闭弹层，不等待 my-role/timeline。
保存删除失败不会阻止游戏同步：渲染函数仍独立禁止这些阶段的推测，同页迟到的旧快照也不能恢复已清空的作用域。
刺杀阶段仍使用原公开邪恶身份/红圈（包括奥伯伦）和黄色目标圈，不将好人身份公开。
