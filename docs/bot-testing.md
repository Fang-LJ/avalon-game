# 机器人测试局与房主结束对局

## 操作

房主在等待大厅点击「添加机器人」，每次添加一个，自动坐到最小空座；机器人列表可逐个移除。房间满员且所有玩家入座后，仍需房主点击「开始游戏」。开局后不能添加、移除或移动机器人。

机器人只用于测试，不是匹配玩家，也不会成为房主。不需要机器人登录 JWT，不开放生产 mock 登录。使用现有 `t_avalon_user.provider=BOT`，不用新增数据库字段、表或 migration。

## 自动行为

- 自动确认身份。
- 队长选队：必须包含自己，其余玩家随机、不重复，人数由现有规则确定。
- 组队投票：70% 赞同、30% 反对。
- 正义任务票：始终成功；邪恶任务票：70% 失败、30% 成功。
- 刺客：从非自己玩家中随机选择，不读取其他人的角色。
- 湖中仙女：随机检查合法目标，排除自己及历史 holder；检查结果不广播。

服务端每秒执行每个测试局最多一个机器人动作（`avalon.bots.tick-ms` 可调整）。动作在事务内先锁定对局行、重新检查阶段及已有提交，再调用原有 GameService。多人同时请求、浏览器断线、服务重启和结束对局后的迟到 tick 都不会重复操作。

## 数据生命周期

包含机器人的已开始对局不进入任何人的历史、胜率或角色统计，复盘接口拒绝访问。数据库中的投票/任务等仅是运行状态，不能当作正式战绩。

- 房主结束测试局：立即关闭房间，按外键顺序清理当局临时数据，所有客户端返回首页。
- 自然结束：显示结算，保留最多约 2 分钟供查看或点击「再来一局」；每 15 秒检查过期数据并清理。清理完成后返回首页。
- 再来一局：创建新 WAITING 大厅，保留玩家和座位，不分配角色；随即删除旧测试局。仍被新大厅引用的机器人账号不会删除。
- 最后一个真人离开等待/结算房间：立即关闭并清理测试房间。
- 移除机器人：只删除等待大厅的机器人成员，以及没有被其他对局引用的 BOT 账号。

清理严格限定于含 BOT 的 FINISHED/CLOSED 游戏及其关联记录，运行中的游戏、真人用户、真人对局和非 Avalon 数据不删除。不执行全库清理、DDL 或 migration。

## 房主结束真人对局

所有进行中阶段都提供「结束本局」，需要二次确认并在后端校验当前成员与房主权限。已开始的真人局进入 FINISHED，`finish_reason=HOST_ENDED`、`winner_alignment=NULL`，保留原记录，但不计胜负/胜率。等待房间直接关闭，不生成已完成战绩。

## API

- `POST /api/avalon/room/{roomId}/bots`
- `DELETE /api/avalon/room/{roomId}/bots/{playerId}`
- `POST /api/avalon/game/{gameId}/end`，返回 `{closed: true|false}`。

全部需要现有 JWT。公共 RoomView 增加玩家 `isBot` 和房间 `testGame`；GameState 增加 `finishReason`，不增加其他玩家的私有角色信息。

## 验证

`cd backend && mvn test`；`cd miniprogram && npm test && npm run check`。

BotGameIntegrationTest 在独立 H2 内存数据库使用现有八表 schema 的兼容语法副本，走真实 JDBC 与 Spring 事务，覆盖 5–10 人真人+机器人整局、10 人 Lady/刺杀、结束/机器人并发、数据清理、真人记录保留与 rematch。不连接生产数据库，不修改 schema 文件。H2 的锁及 JSON 语法并非 MySQL 完全替代，生产 MySQL / 真机 WebSocket 联调仍需单独验证。
