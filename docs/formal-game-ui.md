# 正式对局 UI 收口

本轮只调整小程序展示与本地交互。未修改后端、数据库、状态机、角色配置或游戏规则。

## 布局

- 正式 5～8 人圆桌高 720rpx，9～10 人高 900rpx，任务轨道与圆桌间隔 14rpx。
- 等待大厅继续使用原有圆桌高度和座位位置；正式座位仍根据 seatNo / maxPlayers 固定计算。
- 正式头像为 96rpx，9～10 人为 84rpx；8 人以上隐藏昵称，避免相邻座位文字交叠。
- 正式顶部使用紧凑标题。任务轨道只保留五个状态圆点，移除重复比分。
- 我的身份、退出、房主结束在任务轨道右侧，不再占独立操作行，也不靠近微信胶囊。
- 退出先确认，再调用原 leaveRoom。进行中实际行为仍由后端决定：标记离线，不擅自移除对局玩家。
- 选中玩家用无尺寸变化的外圈：组队青绿、刺杀红、湖中仙女金。王冠、私有视野和“我”仍独立显示。
- 底部保留 220rpx + 安全区的可滚动留白，日志末尾可滚动到固定操作条上方。

## 私密任务弹层

新增 `components/mission-card-overlay`，只负责展示和发送 UI 事件，完全不调用 API。

1. 当前任务成员尚未提交时，首次收到任务快照自动打开弹层。
2. `missionOverlayKey = gameId-missionNo-proposalNo` 记录已经自动打开的任务。
3. 同轮轮询 / WebSocket 更新保留选择、打开状态和暂时收起状态，不重复弹出。
4. 暂时收起不提交；主界面“执行秘密任务”可重新打开。
5. 查看投票会收起弹层；从主界面“返回秘密任务”恢复，保留当前选择。
6. 正义只有成功牌，邪恶同时有成功和失败；复用原 play-card 和卡牌素材。
7. 选牌只修改 missionChoice；确认提交仍调用 room.js 的原提交入口。
8. 原 gameId / missionNo / proposalNo / phase / 成员资格 / GOOD 不能 FAIL 检查保留。
9. 请求期间禁用操作；失败保留弹层和选牌以便重试。成功关闭并清除选择。
10. 换轮、换提案、换局或离开任务阶段清除旧 UI；旧请求成功不能关闭新任务弹层。

## 验证

- 保留原测试，扩展固定座位几何测试：375 / 390 / 430px，5～10 人，包含王冠上方延伸、玩家间距和中心卡边界。
- 新增 formal-game-ui.test.js：任务轨道、三色外圈、私有状态隔离、弹层生命周期、重复提交、失败重试、旧请求防护、退出确认和安全区布局。
- 微信开发者工具 375×812 模拟器，使用拦截请求的 UI 测试数据，没有写入服务器。
- 实测 5～10 人 TEAM_BUILDING 的座位和中心卡无重叠；5～8 人第一屏显示最新提案标题与队长/队伍行。
- 实测 6 / 10 人 MISSION_EXECUTING 的两张卡、收起/重开、查看投票、同轮刷新保留选择、确认提交后关闭；正义只显示一张成功牌。
- 390 / 430px 通过几何模型覆盖；实际手机微信字体缩放、系统安全区和横屏仍需真机核对，未将模拟器测试描述为真机测试。
